## 2.1.0

- Processor разделён на пять изолированных обработчиков: CM, SM, EQ, SBCE и Other.
- Каждый обработчик получает только свой RAW-пакет и возвращает единый результат: Calls, обработанные RAW ID и дополнительные строки.
- Чтение RAW и атомарная запись результата выполняются в одном общем runtime через ACD Load Balancer; отдельных DB-веток у обработчиков нет.
- Для CM направление сначала определяется по полевому словарю транков, затем по `code-dial` и `cond-code` без анализа длины телефонных номеров.
- `cond-code=7` без строки словаря считается исходящим, `cond-code=0` — внутренним, остальные события без маршрутных признаков — входящими.
- Ошибочные и неотвеченные вызовы сохраняют рассчитанное направление и получают соответствующий красный или жёлтый статус.
- Сохранённый CM RAW автоматически возвращается в очередь для пересборки производной таблицы Calls; исходные данные не изменяются.

## 2.0.0

- Collector, Processor и ACD Load Balancer разделены на самостоятельные процессы без общей памяти.
- Сборщики CM, SM, EQ, SBCE и Other передают типизированные RAW-пакеты через локальный Unix-сокет; прямой SQL рабочих RAW-таблиц удалён.
- Processor содержит пять независимых обработчиков и использует отдельные очереди чтения RAW и атомарной записи результата.
- ACD Load Balancer обслуживает три раздельные DB-очереди: `COLLECTOR_WRITE`, `PROCESSOR_READ` и `PROCESSOR_WRITE`.
- Ключи `ACD + источник + экземпляр` обслуживаются по кругу, поэтому одна загруженная ACD не блокирует остальные.
- TCP Collector объединяет всплеск записей в пакеты с окном до 5 мс; максимальный пакет берётся из сохранённого результата теста PostgreSQL.
- До записи в PostgreSQL пакеты сохраняются в локальный SQLite-WAL spool с `synchronous=FULL` по умолчанию.
- Журнал `cdr_load_balancer_jobs` исключает повторную запись RAW, если PostgreSQL уже выполнил COMMIT, а spool остался после аварии.
- Calls, дополнительные данные и перевод RAW в `stat=true` выполняются одной транзакцией; при любой ошибке RAW остаётся необработанным.
- В системную диагностику добавлены служба балансировщика, три очереди, размеры пакетов, spool и ошибки отдельных ACD.
- SYSTEM backup останавливает Collector, Processor и Load Balancer в правильном порядке и сохраняет согласованный снимок БД и очереди.
- Listener при запуске пересобирает файловый cron и переводит CM, SM, EQ, SBCE и Other на единый `collector.py --source`.
- ACD Load Balancer разделён внутри одного процесса на protocol, service, queues, spool и database без изменения Unix-сокета и формата команд.
- Встроенная документация содержит общую логическую схему, схемы Collector и Processor, каталоги источников и таблицы PostgreSQL.
- Контрольный локальный прогон 10 000 синтетических RAW дал около 71 000 строк/с в полностью синхронизированный spool и около 17 000 строк/с в PostgreSQL; результат зависит от оборудования.

## 1.4.1

- Словарь транков остаётся главным источником направления и маршрута CM.
- Если подходящей строки словаря нет, заполненный `code-dial` или `cond-code=7` определяет исходящий вызов.
- Если совпадения в словаре нет и присутствует `cond-code=0`, вызов определяется как внутренний; остальные коды считаются входящими.

- Резервная классификация не изменяет `route-code` и `route-label`: маршрут по-прежнему формируется только по словарю.
- Сохранённые CM RAW автоматически возвращаются в очередь, чтобы Calls были пересчитаны по закреплённому правилу.

## 1.1.0

## Схема данных

- Закреплена единственная актуальная island/source-модель.
- `acd_registry` хранит только технический ключ, имя и состояние ACD.
- Настройки каждой ACD находятся только в `<acd>_config`, `<acd>_servers`, `<acd>_fields`, `<acd>_params`, `<acd>_trunks`, `<acd>_dictionary` и `<acd>_copied_files`.
- Удалены общие таблицы старого контура и неиспользуемые поля конфигурации.
- Отдельная таблица VDN удалена; подписи VDN/Hunt хранятся в словаре. Поле `vdn` в CM CDR сохранено.
- SBCE хранит RAW и Calls только в таблицах инстансов `cdr_<acd>_sbce_<folder>_raw/calls`.
- История старых миграций свёрнута в baseline `0100_current_schema.sql`.

## Runtime

- Listener читает только активные ACD из `acd_registry` и их собственные настройки.
- Все CM-записи сохраняются в RAW; отбор и объединение выполняет processor.
- Debug listener и processor управляется одним полем `<acd>_config.debug_enabled`.
- Добавление SBCE-инстанса сразу создаёт его RAW и Calls таблицы.
- Статус, диагностика, очистка и удаление ACD учитывают реальные SBCE-инстансы.

## Установка и восстановление

- Python-зависимости сведены в один корневой `requirements.txt`.
- Fresh install инициализирует актуальную схему напрямую.
- В релизе `1.1.0` backup и restore были переведены на точную проверку версии архива.
- Restore не содержит преобразований старых общих таблиц, старого EQ и общей SBCE-таблицы.
- Uninstaller создаёт только актуальный `CDR_BACKUP_V1` и не экспортирует старую общую схему.

## Совместимость

`1.1.0` является несовместимым обновлением схемы. Перед установкой обязателен SYSTEM backup и snapshot. Поддержка версий `1.0.x` после перехода не сохраняется.
